## 一、结论（先行）

1. **服务中心体系已成型**：六大角色中心 + 总枢纽 + 问事/民俗/身份三专中心全部在线，架构不需要推倒重构，需要的是**医学后半程补界面**和**接口路径对齐**。
2. **医学 API 对齐度 92%**（170 个 tcm 端点中仅 13 个在 mingli 侧无同名）：核心理由是 G12 预约、G13 回流走了自建路径，与任务书「与 tcm 同构」要求不符——**P0 加别名对齐**。
3. **真正缺口在页面层**：医学闭环目前止于「处方签发」，药房/收费/库存/排班/随访调度五个执行段在 8972 已有 API 但**无操作界面**——医院全流程跑不通的最后一段。
4. **顺路修真两个 P0 干支 bug**（黄历干支 + 择日 v1 全盘），已切 lunar_python 权威源并实测，见 §五。

## 四、流程层诊断

```
建档 → 一帧采集 → AI 诊断 → 命理批注 → 双师审核 → 病历/处方签发 → 【断点】药房配药 → 收费 → 库存扣减 → 排班 → 随访执行
```

- 断点前（诊疗段）：✅ 全闭环，且比 tcm 多命理批注维度（符合「医学能力 = 中医标准智能体 + 命理批注」的定位）。
- 断点后（执行段）：8972 侧 API 大多存在（prescription-api/appointment-api 等），**缺的是操作界面与院内流转编排**——这正是「医院级全过程承载」还没跑通的一段。

## 五、本轮发现并已修的问题（P0，已实测已提交）

| 问题 | 现象 | 修复 | 验证 |
|---|---|---|---|
| 黄历干支 toy 算法 | 2026-08-31 显示「甲酉月」——甲从不配酉，非法干支 | 路由内 subprocess 切 daily-recommendation.py(lunar_python)，覆盖年月日干支+生肖 | 实测返回「丙午年 丙申月 丁丑日 马」与 8911 权威一致 |
| 择日 v1 同病 | 逐日 `(year+month+d)%12` 玩具算法，干支非法、建除错位、冲煞方向错 | 整月一次 subprocess 取每日干支/建除/值神/黄黑道/冲煞，按事件建除过滤 | 实测 2026-09 嫁娶：9-3 庚辰·成·金匮·黄道·冲(甲戌)狗·煞南，全部权威 |
| 太岁 | 仅用年干支 `(year-4)%12`，公式恰好正确 | **无 bug**，刑冲害破为硬编码关系表 | 复核通过 |
| 流年（lifeflow-report / minsu-liunian） | 年干支 `(targetYear-4)%10/%12` 公式合法 | **无 bug** | 复核通过 |
