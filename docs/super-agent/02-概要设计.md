## 二、核心设计决策

### D1 引擎确定性优先，模型生成辅助
排盘、神煞、运气、择日等一切可确定性计算的内容**由引擎产出**；
大模型只负责：意图理解、知识组织、白话表达、行动建议。
→ 从根上消除「模型编造盘面」的不可信来源。BaziQA 36.7% 的教训：
纯生成路线当前不可托付，引擎+检索路线可托付。

### D2 知识三分域
- **正室（mingli 域）**：命理知识，可入报告与批注。
- **参考域（reference）**：医学存量 4.5 万条，只读，供批注人文参考，**禁入诊疗检索域**（G24）。
- **正室（tcm 内化）**：医学知识，只服务诊疗链路。
智能体每次引用必须自报「域 + 出处（src_id + 典籍名）」。

### D3 双文对照原则
所有原典条目 = 原文（不改写）+ 解读（另段标注）。
报告 = 专业段（术语准确）+ 白话段（信众可读）+ 行动段（改进建议可执行）。
三层缺一不出报告。

### D4 校验官独立
校验不依附于生成：独立题库、独立校正库、独立红线巡检（kb-sync-guard + 五红线 + BaziQA 节奏跑）。
任何模型/引擎变更不过校验门不上线（沿用 v9.4 否决机制）。

## 三、馆长智能体（Curator）概要

### 3.1 角色定义
统一对话入口（Web/PWA/微信），对内是调度器，对外是「读过全部典籍的馆长」。

### 3.2 工作流（七步）
1. **听**：接收自然语言（语音/文字/拍照），识别身份（信众/命理师/学习者/患者）。
2. **问**：信息不足时按各工具采集 schema 追问（问答式，零门槛）。
3. **算**：调度对应引擎确定性计算（排盘/评分/择日/合婚…）。
4. **查**：FTS5 检索正室知识，取 top-K 条目附出处。
5. **断**：模型组织「专业段+白话段+行动段」三段报告。
6. **述**：自述知识来源与置信度；涉医学边界自动转介/挂免责声明。
7. **记**：经授权写入个人档案，进入校正闭环（预测点结构化，待应验回收）。

### 3.3 能力矩阵

| 角色 | 服务对象 | 核心能力 | 复用资产 |
|---|---|---|---|
| 问事官 | 信众/大众 | 问答采集→七术+民俗 28 项→白话报告 | 问事服务中心 |
| 副驾 | 命理师/医生 | 实占陪练、追问提示、案例评点 | 断案 222 案+指南 125 案 |
| 导师 | 学习者 | 课程讲授、出题批改、师承路径 | G26 蒸馏管线+题库 |
| 校验官 | 体系自身 | 应验回收、题库平衡、红线巡检 | BaziQA/wiki 702/kb-sync-guard |

## 四、知识层设计

## 五、服务层改造要点

- **问事服务中心**：全部入口收敛到馆长对话式（保留工具卡片作为快捷意图）。
- **排盘中心**：接入副驾「追问引擎」（同五级模型接口契约），盘面点读升级原典引文。
- **传承学堂（新）**：课程列表→章节学习→随堂测→段位认证；学习者身份注册（18+）。
- **问诊台**：维持命医合流唯一批注点，不动（R 系红线）。

## 六、非功能设计

- **性能**：馆长首 token ≤3s（引擎计算并行预取）；FTS5 top-K ≤200ms。
- **可靠**：五红线日巡检；服务变更必过 BaziQA 快测（30 题）+ 全量节奏跑。
- **安全**：密钥全走网关代理（前端零直连）；校正库脱敏；授权分级（信众/命理师/管理员）。
- **可审**：每条 AI 输出可回溯「引擎结果 + 检索条目 + 模型版本」三件套。
