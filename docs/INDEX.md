## 命名规范

**统一使用 UPPER_SNAKE_CASE 后缀版本号**（推荐）：
```
{主题}_{类型}_v{主版本}.md
```
例：`BAZI_KB_AUDIT_v1.md` / `RELEASE_MANAGEMENT_v1.md`

**停用命名**：
- ❌ 纯小写（`bazi_kb_audit.md`） → 与 SHELL 脚本混淆
- ❌ 驼峰（`baziKbAudit.md`） → JS 文件风格，与 doc 视觉混淆
- ❌ 混合多种命名同目录并存 → 难以批量操作

## 维护流程

1. **任何新文档**：必须用 UPPER_SNAKE_CASE_v{主版本}.md
2. **任何新节点产出**：必须更新本文档对应分类
3. **每周五**：心跳自动跑 `scripts/docs-lint.sh` 输出报告
4. **每周日晚**：人工 review 孤立文件，决定 rename / archive / delete
