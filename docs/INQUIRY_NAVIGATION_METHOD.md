# 问诊导航方法论 · 知识总结（tcm-agent R780/R781 实践沉淀）

> 来源：tcm-agent 智能问诊台「AI 副驾驶」追问引擎（提交 1b83c2d / 026c147，2026-08-26）
> 适用范围：任何需要「引导式信息采集」的智能体——问诊、命理排盘咨询、家庭健康随访均可复用此方法。

---

## 一、核心思想

AI 副驾驶的价值不是替医生下结论，而是**在对的时机提示对的问题**。
追问引擎的设计目标：新手照着问就是规范流程，专家扫一眼理由就知道智能体的推理路径。

三条设计原则：

1. **先排危险，再做鉴别**——危重信号未排除前，一切其他问题让路（医疗安全硬要求）。
2. **话术可直接开口**——每条追问都是医生能原样说出口的句子，不是系统术语。
3. **理由必须可见**——每条追问附「为什么问」，建立人机信任、便于教学。

## 二、五级优先级模型

| 优先级 | 类型 | 触发条件 | 示例 |
|---|---|---|---|
| P0 🚩 | 红旗排除 | 症状命中危重信号且关键排除点未覆盖 | 胸闷 →「胸痛放射到左肩/下颌吗？有没有大汗、濒死感？」 |
| P1 🔀 | 鉴别分歧 | 前两名辨证置信度差 < 15% | 「鉴别痰浊闭阻与气滞心胸，问汗出/口渴/二便」 |
| P2 📜 | 方证核对 | 已拟方剂但方证眼目未核实 | 归脾汤 →「胃口怎么样？有没有健忘、面色发黄？」 |
| P3 🔍 | 症状深挖 | 主症的关键鉴别细节未明 | 头晕 →「天旋地转还是昏沉发飘？」（旋转多痰饮，昏沉多气血虚） |
| P4 📋 | 模板缺口 | 标准流程未走完（如十问歌诀） | 「有没有怕冷或发热的感觉？」 |

每轮最多输出 4 条，按优先级截断；排序实现注意 **falsy-0 陷阱**（`PRI[x] || 9` 会把 0 变成 9，须用 `!= null` 判断）。

## 三、智能收敛机制

- **覆盖检测**：每条追问带 `cover` 关键词组，对话文本命中即视为已答，问题自动消失。
- **去重记忆**：`askedKeys` 记录已问问题（医生点击标记），同一会话不重复推荐。
- **动态更新**：每句新对话触发全量重算——第二轮实测中，「没有放射痛」→ 红旗卡自动消退，「叹气后舒服」→ 深挖卡消退，模板缺口兜底浮现。

## 四、方证核对的知识工程（四源派生法）

方证眼目（「用这个方，必须核实哪几个症」）不靠手写，从既有知识资产自动抽取：

| 源 | 抽取方式 | 覆盖量 |
|---|---|---|
| 结构化方剂条目 | 【方名】主治/辨证要点 正则 | 222 首 |
| 证型库 | 临床表现 + 代表方剂 | 40 首 |
| 辨证引擎方证表 | 引擎推荐路径兜底 | 6 首 |
| 选方规则表 | match/pick 源码只读抽取（零重构） | 26 首 |

合计 294 首派生 + 15 首手写精修（精修优先命中，派生兜底）。

**词法规则**：舌脉词（脉浮、苔腻、舌红）自动过滤——那是望诊/切诊的采集域，不是问诊语言。

## 五、接口契约（可移植）

```json
{
  "followups": [
    { "key": "red:胸痛", "ask": "话术原文", "why": "追问理由", "priority": "red|diff|formula|deep|tenq", "source": "红旗排除" }
  ]
}
```

前端按 priority 色阶渲染（红>黄>蓝>青>灰），title 悬浮显示 why + source。

## 六、复用指引

- **命理宝鉴**：同一模型可迁移为「排盘导航」——P0 改为「关键信息缺失」（出生时辰不确定→先定时辰），P1 为「格局分歧鉴别」（两可格局的取舍问），P2 为「断语核对」（断语所依据的事实未核实），P3 为「应期深挖」，P4 为「标准问卷缺口」。话术+理由结构原样适用。
- **家庭生活助手**：迁移为「家庭健康随访导航」——P0 为「危险信号排查」（老人跌倒、儿童高热），P3 为「症状随访深挖」，配合穿戴数据与服药提醒；方证核对层可降级为「在用药物核对」（禁忌/重复用药）。

## 七、已验证的工程教训

1. 优先级排序的 falsy-0 bug 会让最高优先级沉底——排序权重必须显式判空。
2. 追问不上手写库就上没有意义：覆盖度 < 推荐路径全集时，医生会怀疑智能体「漏问」，信任崩塌比没有更糟。
3. 每条追问必须可收敛（能消失），否则界面变成噪音墙。
